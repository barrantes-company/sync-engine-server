*   **Gestión de Estados Compartidos**:

En escenarios de concurrencia (>5 solicitudes de escritura simultáneas o ráfagas de mensajes), el event loop de Node.js se bloquea, degradando el throughput del servidor.
    *   **Cliente**: El estado en [`public/index.html`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/public/index.html) reside exclusivamente en variables de memoria en tiempo de ejecución (`currentUser`, `activeContactSyncId`, `contactsMap`, `renderedMessageIds`, `activeConversationMessages`). A partir de dicho umbral, los mensajes históricos se destruyen irreversiblemente sin archivado ni paginación por cursores.

*   **Latencia en el Envío de Mensajes**:

### 2. PROPUESTAS PARA EL GRAN SALTO DE CALIDAD (Features Avanzadas)

#### Sincronización Offline y Resiliencia
1.  **Persistencia Local con IndexedDB**:
    *   Sustituir el almacenamiento en memoria volátil del cliente por un motor local basado en `IndexedDB` (utilizando la API estándar o un wrapper tipado de bajo overhead como Dexie.js o IDB).
    *   Almacenar esquemas locales: `conversations`, `messages`, `contacts` y `outbox`. Al iniciar o alternar chats, la UI carga instantáneamente los mensajes desde disco local (0 ms de latencia de red) y actualiza el delta desde el servidor en segundo plano.
2.  **Patrón Outbox e Idempotencia**:
    *   Todo mensaje enviado sin conexión se almacena en `outbox` con UUID v4 generado por el cliente, estado `pending` y timestamp de emisión.
    *   Al restablecer conexión (evento `online` o reconexión de Socket.IO), un worker procesa la cola en ráfaga. El servidor valida el UUID para descartar duplicados antes de insertar.
3.  **Conflict-free Replicated Data Types (CRDTs)**:
    *   Adoptar estructuras CRDT de tipo LWW-Element-Set (Last-Write-Wins) o registros causales basados en Vector Clocks para resoluciones concurrentes de estados (mensajes editados, eliminados o estados de lectura) entre múltiples terminales de un mismo usuario que operaron desconectados simultáneamente.

#### Seguridad y Privacidad
1.  **Cifrado de Extremo a Extremo (E2EE - Protocolo Signal)**:
    *   *Estado Actual*: Los mensajes y notas de voz residen en texto claro dentro de [`data/sync_db.json`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/data/sync_db.json) y en el sistema de archivos del servidor.
    *   *Implementación Propuesta*: Integrar el algoritmo Double Ratchet combinado con X3DH (Extended Triple Diffie-Hellman). Los clientes generan y almacenan sus claves privadas de identidad (`IdentityKey`), claves de firma precalculadas (`SignedPreKey`) y claves efímeras (`OneTimePreKeys`) en el almacén criptográfico seguro local (`SubtleCrypto` no exportable en Web; Android Keystore / iOS Keychain en aplicaciones nativas).
    *   El servidor se convierte en un relé ciego (*blind relay*): únicamente enruta paquetes criptográficos (`ciphertext`, `ephemeral_key`, `nonce`, `ratchet_step`).
2.  **Autodestrucción Criptográfica de Mensajes (TTL)**:
    *   Temporizador asociado al estado de lectura de cada mensaje. Cumplido el TTL, los clientes eliminan de forma segura el registro en su base de datos local y sobreescriben la clave simétrica efímera de la cadena de trinquete (*ratchet chain*), imposibilitando la recuperación forense.

#### Experiencia de Usuario Premium
1.  **Búsqueda Global Indexada Local (FTS)**:
    *   Motor de búsqueda de texto completo en el cliente ejecutado en un Web Worker utilizando BM25 (mediante MiniSearch o SQLite FTS5 compilado a WebAssembly). Permite filtrar y resaltar palabras clave en milisegundos a través de todo el historial local sin remitir consultas al servidor, preservando la privacidad.
2.  **Extracción Asíncrona de Open Graph (Desacoplada)**:
    *   Separar la entrega del mensaje de la generación de metadatos. El mensaje debe emitirse de inmediato con estado `delivered`. El backend procesa la extracción de URL mediante un worker secundario y emite un evento ligero `message-preview-updated` cuando la tarjeta gráfica esté construida.
3.  **Presencia y Mecanismos de Debounce**:
    *   Implementar reguladores de 2,500 ms con descarte de ráfagas para los eventos `typing` y `recording-audio`. Transcurridos 3 segundos sin pulsaciones o interacción en el micrófono, el cliente emite la señal de parada, evitando saturación de paquetes de señalización en Socket.IO.
4.  **Transiciones Aceleradas por Hardware**:
    *   Implementar la View Transitions API (`document.startViewTransition`) en navegadores compatibles para la navegación fluida entre la lista de conversaciones y el chat activo, combinada con contención de layout CSS (`contain: content`) en los ítems de mensaje.

#### Bucle del Abogado del Diablo: Modos de Falla del Sistema

1.  **Condición de Carrera en Escritura (`sync_db.json`)**: [`writeDb`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/db.js#L42-L47) genera un archivo temporal y renombra síncronamente. Si dos peticiones concurrentes completan lecturas previas a una escritura ajena, la última en ejecutar sobrescribe la primera, provocando pérdida silenciosa de registros.
2.  **Saturación del Bucle de Eventos por Scraping**: [`fetchUrlMetadata`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/server.js#L85-L167) bloquea la resolución del mensaje durante un fallo de red o latencia del destino HTTP, incrementando la cola de microtareas del proceso Node.
3.  **Fuga de Conexiones en Mapas de Memoria**: Si un cliente móvil entra en modo suspensión profunda (*deep sleep*) sin emitir el paquete `disconnect` de WebSocket, su identificador permanece registrado en `onlineUsers` ([`server.js:454`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/server.js#L454)), intentando despachar eventos a sockets muertos hasta que el ping timeout expire.
4.  **Desborde de Memoria en Navegador Móvil**: La inserción continua de elementos multimedia sin reciclaje de nodos DOM colapsa la pestaña en dispositivos con menos de 4 GB de RAM.

#### Suposición Técnica Crítica (Colapsable)
*El diseño actual asume que todos los clientes conservan una conexión de red ininterrumpida y que el servidor único es el único punto de resolución de estado.*
Si esta suposición cae durante una microdesconexión de red celular de 5 segundos, todos los mensajes emitidos por el interlocutor durante ese intervalo se pierden de la vista del cliente receptor sin posibilidad de autorrecuperación, a menos que el usuario reinicie la sesión o seleccione manualmente otro contacto para forzar un re-fetch.

#### Manejo de Alternativas de Diseño
*   **Problema**: Persistencia en archivo único JSON síncrono ([`data/sync_db.json`](file:///c:/REPOSITORIOS_BARRANTESCO/sync-engine-server/data/sync_db.json)).
*   **Consecuencia**: Bloqueo del hilo de ejecución en lecturas/escrituras concurrentes, falta de índices y pérdida total de datos ante fallos de alimentación durante el guardado.
*   **Solución Recomendada**: Sustituir el almacenamiento en archivo plano por una base de datos embebida transaccional (SQLite en modo WAL - Write-Ahead Logging) o PostgreSQL. Permite escrituras concurrentes no bloqueantes, soporte ACID completo y consultas con cursores paginados.

def verify_hmac_signature(body: bytes, signature_header: Optional[str]) -> bool:
    if not signature_header:
        return False
    expected = hmac.new(WEBHOOK_SECRET, body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(f"sha256={expected}", signature_header)

@app.post("/api/v1/webhook/incoming", status_code=status.HTTP_202_ACCEPTED)
async def receive_external_webhook(
    request: Request,
    payload: WebhookMessagePayload,
    x_sync_signature: Optional[str] = Header(None)
):
    raw_body = await request.body()
    if not verify_hmac_signature(raw_body, x_sync_signature):
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Firma criptográfica inválida")

    if not sio.connected or not app_state["is_authenticated"]:
        raise HTTPException(status_code=status.HTTP_503_SERVICE_UNAVAILABLE, detail="El gateway no está enlazado a la sesión de mensajería")

    message_content = (
        f"🔔 *Alerta de Automatización ({payload.source})*\n"
        f"*{payload.title}*\n"
        f"{payload.description}"
    )

    await sio.emit("send-private-message", {
        "toSyncId": payload.target_sync_id.upper(),
        "text": message_content,
        "type": "text",
        "clientMsgId": f"wh_{int(asyncio.get_event_loop().time() * 1000)}"
    })

    return {"status": "dispatched", "target": payload.target_sync_id}

@app.post("/api/v1/ai/summarize", status_code=status.HTTP_200_OK)
async def api_trigger_summary(req: SummarizeRequest):
    if not app_state["auth_token"]:
        raise HTTPException(status_code=status.HTTP_503_SERVICE_UNAVAILABLE, detail="Gateway no autenticado")

    client: httpx.AsyncClient = app_state["http_client"]
    url = f"{SYNC_SERVER_URL}/api/messages/{req.contact_sync_id.upper()}"
    headers = {"Authorization": f"Bearer {app_state['auth_token']}"}

    resp = await client.get(url, headers=headers, timeout=10.0)
    if resp.status_code != 200:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Historial inaccesible o contacto inexistente")

    messages = resp.json().get("messages", [])
    selected = messages[-req.max_messages:]
    conversation_text = "\n".join([
        f"[{m.get('fromId', 'USR')}]: {m.get('text', '')}"
        for m in selected if m.get("text") and not m.get("deletedForEveryone")
    ])

    summary = await generate_llm_summary(conversation_text)
    return {
        "contactSyncId": req.contact_sync_id.upper(),
        "messagesAnalyzed": len(selected),
        "summary": summary
    }
